# Publication checklist

Run this checklist before every public release.

## Data and security

- [ ] All data is synthetic, anonymised or authorised for publication.
- [ ] No credentials, tokens, connection strings or private endpoints exist.
- [ ] Workbook queries and Power BI connections do not reference private paths or systems.
- [ ] Hidden sheets, comments, notes and embedded files were reviewed.
- [ ] Office and Power BI metadata was inspected.
- [ ] Git history was checked for previously committed sensitive content.

## Portfolio quality

- [ ] The README states the business problem before the tools.
- [ ] The method and validation steps are understandable.
- [ ] Results do not claim more than the evidence supports.
- [ ] Screenshots are readable and contain no personal information.
- [ ] File and folder names are consistent.
- [ ] Links work from the GitHub interface.

## Repository quality

- [ ] Default branch is `main`.
- [ ] Repository description and topics are configured.
- [ ] The most relevant project is pinned on the profile.
- [ ] The public URL is added to LinkedIn Featured.
- [ ] A release tag is created for a stable portfolio version.
